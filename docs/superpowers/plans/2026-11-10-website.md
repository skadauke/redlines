# The website: the real editor on the page, and a site that is current — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The website says honestly what Redlines has built and planned, keeps its icons in step with
the app's, and replaces its two drawings of the editor with the real editor, lazy-loaded, with a
scripted Claude the visitor asks; the deploy and the push trigger wait for Stephan's yes.

**Architecture:** A new private workspace package, `apps/website-embed`, bundles the editor,
formatting, review and the agents plugin's run machinery with a scripted provider into one hashed
ES module, a stylesheet and four woff2 fonts under `website/public/embed/`, described by Vite's
manifest. The static Next.js site reads the manifest at build, renders data-driven fallbacks on the
server, and mounts `mountDemo` into each sheet when it nears the viewport; the page draws the
controls. Node scripts hold the site to `docs/design.md` §4 and to the icon masters; vitest covers
the embed and the plugins; Playwright covers the built page in Chromium and WebKit.

**Tech Stack:** TypeScript (strict), CodeMirror 6 through `@redlines/*`, Vite 8, vitest 5 with
happy-dom, Next.js 16 (static export), React 19, Tailwind 4, `node:test`, Playwright with
`@axe-core/playwright`, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-10-website-design.md`. Read it with this plan: every
"Call:" there is a decision this plan builds, and the section names below are its.

## Global Constraints

- Node >=22, pnpm 10.28.0. `website/` stays an npm project outside the workspace; workspace commands
  run from the repo root. In a fresh worktree: `pnpm install`, then `cd website && npm install`.
- Before each commit that touches the workspace: `pnpm typecheck && pnpm lint && pnpm test &&
  pnpm format:check`. Before each commit that touches `website/`: `cd website && npm run build`,
  plus the website checks the task names.
- Commit subjects in the repo's form (`Website: …`, `Embed: …`, `Review: …`, `Agents: …`, `CI: …`,
  `Docs: …`) with the issue; every commit message ends with the line
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Nothing publishes before Task 18:** no run of `deploy-website.yml`, no `push` trigger in it, no
  workflow run by hand. Task 18 acts only on Stephan's yes.
- The page makes no request to any origin but its own, and writes nothing to the visitor's machine
  but `redlines.mark` in `localStorage`.
- Red is the brand's only: notices, errors and disabled controls are gray. Interface text is at least
  13 px (12 px for a caption, a timestamp or a hint).
- The bundle targets `['es2022', 'safari16']`. Its JS budget is the first build plus 3%, rounded up
  to a KB (1 KB = 1,024 bytes); CSS 10 KB gzipped; fonts 105 KB as served.
- The visitor is `{ handle: 'ada', name: 'Ada Lovelace' }`; the people record is
  `[{ handle: 'claude-ada', color: 2 }, { handle: 'bo', color: 3 }]`; typing is
  `{ smartPunctuation: true, spellCheck: false, closePairs: false }`; each demo starts, and resets
  to, Redlines with Track Changes on.
- A panel loads after `load`, once within 600 px of the viewport, on idle; with
  `navigator.connection.saveData`, only on "Try it here".
- The comparison's other products' cells and its "as of October 2026" don't change.

## Review Focus

1. A visitor pastes a paragraph from another site that holds an image, with Track Changes off (or
   accepts such a paste): the page fetches nothing from that site. Test in Task 12.
2. The system switches between light and dark while a panel is open: the editor follows at once.
   Test in Task 6.
3. A 320 px-wide phone: the controls wrap, nothing scrolls sideways, and the review bar stays in the
   sheet. Tests in Tasks 12 and 16.
4. The bundle loads but `mountDemo` throws (an old browser, a bad build): the fallback stays, no
   control appears, and the visitor sees no error. Test in Task 11.
5. Both panels at once: Reset in the hero while Claude runs in the agent panel leaves the run and
   its edit alone, and the run touches nothing in the hero. Test in Task 15.

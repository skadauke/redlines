# Tables Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A table is edited as a table in Clean, Simple and Redlines (cells you click and type in, rectangles of cells, rows and columns inserted, deleted and moved, ranges copied and pasted), with every change tracked as Word tracks it, while the file stays plain GFM Markdown.

**Architecture:** The table stays its Markdown source. A new layer in `packages/editor/src/table/` reads the tables from the syntax tree (incrementally) and lays the source out as a table through CodeMirror's block wrappers, line decorations and outer marks; pipes, padding and the delimiter row are hidden and the caret steps over them as atoms. Keys, the mouse and the clipboard compute plain edits that the existing tracked layer records through `trackedEdit` or `untrackedEdit`; row and column operations are new functions in `@redlines/format` (`table.ts`, `table-ops.ts`) that write the forms format §3.7 defines, with eight new rules. The grips, the + and the Table menu's commands are the `tables` plugin.

**Tech Stack:** TypeScript (strict), CodeMirror 6 (view 6.43.14: `EditorView.blockWrappers`, `outerDecorations`, `atomicRanges`, `mouseSelectionStyle`), `@redlines/format`, vitest (Node and happy-dom), micromark 4.0.2 with `micromark-extension-gfm-table` as the oracle, Tauri v2 menus, a small Swift program for the WebKit check. pnpm is `npx -y pnpm@10.28.0`; git is `/usr/bin/git`.

**Spec:** `docs/superpowers/specs/2026-11-10-tables-design.md` (the design; read it first, every "Call:" in it is decided), with `docs/format.md` §3.7 as the source of truth for the marks and `docs/research/tables.md` behind it. The prototype is the throwaway code the design rests on: **the prototype, at the path the dispatch gives** (outside the repo; never copy it into the repo, cite it in comments by file only). Its table layer is `editor/src/preview/grid.ts` (`tablesOf`, `rowOf`, `pipesOf`, `rectOf`, `cellAt`, the ghost row and empty-cell widgets, the mouse style, the keys); its WebKit harness is `webkit/check.swift` with `webkit/checks.js`, `webkit/ghosts.js` and `webkit/bench.js`; its format models are `model/plain.ts` and `model/combos.ts`. Stage 1 is porting and hardening it, not research.

## Review Focus

The inputs the design implies and no row of its tables exercises, most likely first; each line has its test in the named task.

1. **A table in a CRLF file** (Tab's new row, Return's `<br>`, clearing cells, an inserted row): the file's own line breaks are written, and rejecting gives every byte back. Tasks 1.4, 1.11, 1.12.
2. **Blocks next to a table:** two tables a blank line apart, a table directly before a struck block widget, before the ledger, at the very start or end of the document. Each table is its own wrapper, the blank line and the widget are in none, and ↓ from the last row opens the empty paragraph. Tasks 1.7, 1.10.
3. **Pipes and escapes in cells:** `\|`, a pipe in a code span (which starts a cell, as GFM and GitHub read it), an image or link in a cell, an emoji or combining mark at a cell's edge. Cell ranges are right, typing a `|` writes `\|`, no key splits a surrogate pair. Tasks 1.2, 1.3, 1.11.
4. **Ragged and pipe-less rows:** a row with fewer cells than the header, one with more, a row without a leading pipe, an empty header cell. No key throws, no text is lost, the caret has no stop in a cell GFM doesn't show. Tasks 1.2, 1.9, 4.4.
5. **Composing in an empty cell, and tables inside a quote or list:** an update during composition leaves the cell's filler in place; a table inside a quote or list item stays source, with no wrapper. Tasks 1.7, 1.9.

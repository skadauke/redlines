# v0.2 spike findings

What the throwaway proved on Nov 5, 2026, on macOS 27.0.1, arm64, with Claude Code 2.1.318 and Codex 0.166.0. Every later agent task reads this. Where this and the plan differ, this wins.

The throwaway is on the local branch `spike/v0.2` and never merges.

## In short

| Question | Answer | How it's known |
| -------- | ------ | -------------- |
| Does the relay work? | **Yes.** Agent → `redlines mcp --relay` → Unix socket → Tauri → webview → live CodeMirror → answer back | Real Codex, real model, in the signed app. Real `claude` with a scripted model, in the signed app |
| Does the nested program survive signing? | **Yes.** `externalBin`, signed, notarized, stapled, universal, `spctl` accepts it | Done twice, below |
| Does a toolbox edit race typing? | No. A real typed transaction landed during a run, and both survived | Every relay run |
| Can Codex's reads be limited to the folder? | **Yes: `readLimit: 'folder'`**, by a permission profile, not by `--sandbox read-only` | Real runs, the OS refused each read |
| Do Codex's toolbox calls need approval? | **Yes, unless told otherwise.** `default_tools_approval_mode="approve"` fixes it | Real runs, both ways |
| Does a repo's `.codex` run? | No, with `--ignore-user-config` | Markers, with a positive control |
| Do a repo's hooks and `.mcp.json` reach Claude? | No, with either line below | Markers, with a positive control |
| Do Claude's reads stop at the folder? | **Only with `--restricted`.** With `--setting-sources user`, a person's own settings can widen them | Real binary, scripted model |
| **Does `--setting-sources user` or `--restricted` keep the plan sign-in?** | **Not proved.** Claude's sign-in on this Mac has expired | See below |

Two things no one asked about, and both change the build:

1. **Codex hands the model the person's ChatGPT connectors.** Under the plan's flags it had `mcp__codex_apps__github_create_commit`, `github_delete_file`, `github_enable_auto_merge` and many more, and a web tool. That breaks "no other way to change anything". The final line turns them off.
2. **A toolbox that fails to start doesn't fail the run.** Both agents carry on without it and exit 0. The run has to notice.

- [ ] `--restricted` keeps the plan sign-in. `--bare` proves nothing here: it gives the same message when the token is stale.
- [ ] `--setting-sources user` keeps the plan sign-in.
- [ ] What a real model's stream looks like (thinking blocks, `real-run.jsonl`).
- [ ] How long a real Claude run takes.
- [ ] What `claude auth status` prints when signed in, and with `CLAUDE_CODE_SIMPLE=1` set.

**After `claude auth login`,** two scripts in `apps/desktop/spike-tools/` on the spike branch do all five, with two haiku runs and two relay runs through the stapled app: `setup.sh`, then `claude-real.sh`. Then tick these, add `plugins/agent-claude/fixtures/real-run.jsonl`, and correct the line if needed.

**The fallback if `--restricted` loses the plan sign-in:** use `--setting-sources user`, which needs no other change to the line. Reads are then held only while the person's settings don't widen them, so before a run read `permissions` in `~/.claude/settings.json` (a settings file, not a credential): if `allow` holds a bare `Read`, `Grep` or `Glob`, or `additionalDirectories` isn't empty, the provider reports `readLimit: 'machine'` for that run, and the question says so. If neither line keeps the sign-in, stop and tell Stephan, because then the demo can't run on a plan.

## The Claude line

Run in the folder, with stdin closed and a cleaned environment (below).

```bash
claude -p "<prompt>" \
  --output-format stream-json --verbose \
  --restricted \
  --permission-mode dontAsk \
  --tools "Read,Grep,Glob" \
  --allowedTools "mcp__redlines__view,mcp__redlines__read_thread,mcp__redlines__str_replace,mcp__redlines__comment,mcp__redlines__reply,mcp__redlines__status" \
  --mcp-config '{"mcpServers":{"redlines":{"command":"<Redlines.app>/Contents/MacOS/redlines","args":["mcp","--relay","<socket>"]}}}' \
  --strict-mcp-config \
  --settings '{"disableAllHooks":true}' \
  --append-system-prompt "<voice>"
```

At This document: `--tools ""`, in a fresh empty temp folder. The model is then offered only the six toolbox tools.

**Minimum version: 2.1.318,** the one tested. 2.1.201 has no `--restricted`. An older program fails loudly on the unknown flag.

**Why `--restricted` and not the plan's `--setting-sources user`:**

| A real `claude`, scripted to try each | `--setting-sources user` | `--restricted` |
| ------------------------------------- | ------------------------ | -------------- |
| Read a file in the folder, and its `.env` | Works | Works |
| Grep in the folder | Works | Works |
| Read, Grep or Glob outside the folder | Denied | Denied |
| Read a symlink in the folder that points out | Denied | Denied: "resolves through a symlink" |
| **The same, when `~/.claude/settings.json` has `permissions.allow: ["Read"]`** | **Read and symlink work** | **Denied** |
| **The same, when it has `permissions.additionalDirectories`** | **Read, Grep and Glob work** | **Denied** |
| Bash, Edit, Write, WebFetch | "No such tool" | "No such tool" |
| Toolbox calls | Run, no prompt | Run, no prompt |
| A repo's `.mcp.json` and `.claude/settings.json` hooks | Don't run | Don't run |
| The person's own hooks, without `disableAllHooks` | Run | Don't run |
| The person's plugins | Load | Don't load |
| The person's `~/.claude/CLAUDE.md` reaches the model | **Yes** | No |
| A repo's `CLAUDE.md` reaches the model | No | No |

The plan's line holds the limit only for someone whose settings don't widen it, and the spec's rule is that a level has to be what the agent really does. `disableAllHooks` is redundant under `--restricted`. It's harmless, so it stays.

**The positive control:** with neither flag, the same repo's `.mcp.json` server and its `SessionStart` and `UserPromptSubmit` hooks all wrote their marker files. Under each line above, none did.

**What `--restricted` costs:** it ignores all of the person's settings, including a `model`, an `apiKeyHelper` or `env` there. The model becomes the default unless Preferences passes `--model`. Someone who signs in only through an `apiKeyHelper` won't be signed in. A plan and `ANTHROPIC_API_KEY` aren't settings. The first still needs its check above.

### The environment

Started from Finder the app has a clean environment. Started from inside a Claude Code session, as a developer might, it inherits `CLAUDE_CODE_SIMPLE=1` (which is what `--bare` sets: no plan sign-in), `ANTHROPIC_BASE_URL`, `CLAUDE_CODE_OAUTH_SCOPES` and about thirty others. When `CLAUDECODE` is set, remove `CLAUDECODE`, every `CLAUDE_CODE_*` and `CLAUDE_AGENT_SDK_*`, and `ANTHROPIC_BASE_URL` before starting a program. `env -u CLAUDECODE -u CLAUDE_CODE_ENTRYPOINT -u CLAUDE_CODE_SSE_PORT` isn't enough, because it leaves `CLAUDE_CODE_SIMPLE`. That `CLAUDE_CODE_SIMPLE` loses the sign-in comes from `claude --help`, and the check below tries it.

## The Codex line

Run with stdin closed, because with a piped stdin Codex reads it and adds it to the prompt.

```bash
codex exec --json --strict-config \
  -C "<folder>" --skip-git-repo-check \
  --ignore-user-config --ignore-rules \
  -c 'approval_policy="never"' \
  -c 'default_permissions="redlines"' \
  -c 'permissions.redlines.filesystem={":minimal"="read",":project_roots"={"."="read"},":slash_tmp"="deny","<folder codex was found in>"="read","<folder of its real path>"="read"}' \
  -c 'mcp_servers.redlines.command="<Redlines.app>/Contents/MacOS/redlines"' \
  -c 'mcp_servers.redlines.args=["mcp","--relay","<socket>"]' \
  -c 'mcp_servers.redlines.default_tools_approval_mode="approve"' \
  -c 'developer_instructions="<voice>"' \
  --disable apps --disable plugins --disable image_generation --disable goals --disable skill_search \
  --disable tool_suggest --disable computer_use --disable browser_use --disable in_app_browser \
  -c 'web_search="disabled"' \
  "<prompt>"
```

At This document: leave out `":project_roots"`, and use `-C` with a fresh empty temp folder. Write the values as JSON strings, which TOML reads the same way. The folder's own path never goes in the profile, so its quotes and spaces can't break it.

**Minimum version: 0.166.0,** the one tested. `--strict-config` makes a too-old program fail loudly rather than ignore a key, so the read limit can't quietly go away. Without it, an unknown key gives only an `item.completed` of type `error`, and the run goes on.

**Each part, and what happens without it:**

| Part | Why |
| ---- | --- |
| `default_tools_approval_mode="approve"` | Without it every toolbox call fails: `MCP tool call requires approval, but approval policy is never` (`real-approval-refused.jsonl`) |
| The profile, not `--sandbox read-only` | `--sandbox read-only` blocks writes and the network but reads anything: it read a file outside the folder. **Don't pass both.** With both, the session's recorded file policy changes, and it wasn't worth finding out which wins |
| The two folders for Codex's own program | Without them: `failed to load AGENTS.md instructions … sandbox-exec: execvp() of '/opt/homebrew/bin/codex' failed: Operation not permitted`. Naming the file isn't enough, it takes the folders. Here that's `/opt/homebrew/bin` and `/opt/homebrew/Caskroom/codex/0.166.0/bin` |
| `":slash_tmp"="deny"` | `:minimal` otherwise lets it read and write `/tmp` |
| `--ignore-user-config` | Keeps the ChatGPT sign-in. Without it the person's `config.toml` applies, with its MCP servers, `notify` and plugins, and a repo they trusted runs its own MCP servers |
| `--disable …` and `web_search` | See below |
| `--skip-git-repo-check` | A folder that isn't a repo works, and `:project_roots` is then that folder |

**Sign-in and detection:** `codex login status` prints `Logged in using ChatGPT` and exits 0, or `Not logged in` and exits 1.

### `readLimit: 'folder'`, and how that's known

With this profile a real model was asked to try each thing, and macOS refused them: the outcome is in Codex's own session log.

| Attempt | Result |
| ------- | ------ |
| `cat inside.txt`, in the folder | Worked |
| `cat <folder outside>/secret.txt` | `Operation not permitted` |
| `cat link-out.txt`, a symlink pointing out | `Operation not permitted` |
| `ls ~` | `Operation not permitted` |
| `touch x-inside`, in the folder | `Operation not permitted` |
| `apply_patch` in the folder | `patch rejected: writing is blocked by read-only sandbox` |
| `view_image` outside the folder | `Operation not permitted (os error 1)` |
| A helper from `multi_agent_v1__spawn_agent`, reading and writing outside | Both refused: helpers inherit it |
| `curl` | No network |

`codex sandbox -P <name> -c 'permissions.<name>.filesystem=…' -C <folder> -- <command>` tests a profile with no model and no cost. `/etc` and system folders stay readable, which `:minimal` needs. `git` doesn't work inside (`fatal: unable to access '~/.gitconfig'`). The agent still has `cat`, `grep` and `find`.

So Codex can offer "Just this document" too, and the question can say "Let Codex read this folder?". The `'machine'` value stays in the types, for the fallback above and for agents to come. An install under `npm` and nvm wasn't tried, and needs more folders in the profile. If they're missing it fails out loud at the start, with the `execvp` line above.

### What else reaches the model

`--ignore-user-config` skips `config.toml` only. `~/.codex/AGENTS.md` still loads, and a run tried to read a file it names (and was refused). A repo's `AGENTS.md` loads too. That's a repo's words in the prompt, as with any read of the folder. `-c project_doc_max_bytes=0` should turn it off, but that wasn't tried.

### A repo's `.codex`

The scratch repo's `.codex/` held a `config.toml` (an MCP server, `notify`, `sandbox_mode = "danger-full-access"`), `hooks.json` and a `.rules` file, each writing a marker. Real runs with `--ignore-user-config --ignore-rules` left no marker.

The positive control, with a throwaway `CODEX_HOME` that marks the repo trusted: without `--ignore-user-config` its MCP server ran. With it, nothing ran, because trust lives in the file it ignores, and `-c projects…trust_level` is refused as unknown. `notify` isn't honored from a repo at all, even when trusted. The repo's hooks didn't run in the control either (hooks also need their own trust), so the control doesn't show that they would have.

Traps for the parser:

## The relay

A Tauri command binds one listener in a new `0700` folder under `std::env::temp_dir()`, sets the socket to `0600`, and hands lines to the webview through a `Channel`. `redlines mcp --relay <socket>` is two threads and no JavaScript. The path was 61 bytes against the limit of 104.

**The two clients don't speak alike.** Task 23's server has to take both.

```jsonc
// Claude asks first, with a string id, and takes -32601 as "use the old way". The handshake then goes on.
{"jsonrpc":"2.0","id":"server-discover-probe-1","method":"server/discover","params":{"_meta":{"io.modelcontextprotocol/protocolVersion":"2026-07-28", /* … */}}}
{"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{"roots":{"listChanged":true},"elicitation":{"form":{},"url":{}}},"clientInfo":{"name":"claude-code","version":"2.1.318", /* … */}},"jsonrpc":"2.0","id":0}
{"jsonrpc":"2.0","method":"notifications/initialized"}
{"method":"tools/list","jsonrpc":"2.0","id":1}
{"method":"tools/call","params":{"name":"status","arguments":{"text":"Reading the folder"},"_meta":{"claudecode/toolUseId":"toolu_…","progressToken":2}},"jsonrpc":"2.0","id":2}

// Codex
{"jsonrpc":"2.0","id":0,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{"experimental":{"codex/auth-change":{}},"elicitation":{"form":{},"url":{}}},"clientInfo":{"name":"codex-mcp-client","title":"Codex","version":"0.166.0"}}}
```

Answer with the `protocolVersion` you were asked for, ignore `_meta`, and echo ids of either type. The agents' MCP servers run outside Codex's sandbox, so the profile doesn't get in the way of the socket, even with `:slash_tmp` denied.

**A toolbox that can't start fails silently.** An accident proved it for Codex: a 0-byte `redlines` gave `turn.completed`, exit 0, and the message "Redlines tools aren't available", with no event at all about the server (`real-toolbox-wont-start.jsonl`). Claude shows it in `system/init` (`mcp_servers: [{"name":"redlines","status":"failed"}]`, `tools: []`) and also ends with `is_error: false`, exit 0 (`scripted-toolbox-wont-start.jsonl`). So a run counts as failed if the relay never saw `initialize` by the time the program ended, or if Claude's init says anything but `connected`.

## The nested program

**The route:** Tauri's `bundle.externalBin`, in `tauri.conf.json`:

```json
"bundle": { "externalBin": ["binaries/redlines"] },
"build": {
  "beforeDevCommand": "scripts/build-redlines && pnpm dev",
  "beforeBuildCommand": "scripts/build-redlines && pnpm build"
}
```

`scripts/build-redlines` builds the crate and writes to `src-tauri/binaries/`. `TAURI_ENV_TARGET_TRIPLE` is `universal-apple-darwin` for a universal build, and then **three** files are needed: `redlines-aarch64-apple-darwin` and `redlines-x86_64-apple-darwin` (tauri-build wants one for each `cargo` run) and `redlines-universal-apple-darwin` (the bundler takes this one, made with `lipo`).

```bash
APPLE_SIGNING_IDENTITY="Developer ID Application: …" pnpm tauri build --target universal-apple-darwin --bundles app
codesign --verify --deep --strict Redlines.app                        # valid on disk, satisfies its Designated Requirement
ditto -c -k --keepParent Redlines.app Redlines.zip
xcrun notarytool submit Redlines.zip --keychain-profile redlines-notary --wait   # Accepted, 28 s
xcrun stapler staple Redlines.app                                     # worked
spctl --assess --type execute --verbose=2 Redlines.app                # accepted, source=Notarized Developer ID
env -i PATH=/nonexistent Redlines.app/Contents/MacOS/redlines --help  # exit 0: no Node on the PATH
env -i PATH=/nonexistent Redlines.app/Contents/MacOS/redlines view doc.md   # exit 0: QuickJS printed the newest text
```

Tauri signs the nested program itself, with the hardened runtime (`flags=0x10000(runtime)`), and no entitlement was needed. QuickJS doesn't need one, since it doesn't compile to machine code. The main binary is `redlines-desktop`, so the names don't collide. A real agent then ran the nested program from the stapled app, through the relay.

| Size | Bytes |
| ---- | ----- |
| `redlines`, arm64 | 1,205,056 |
| `redlines`, x86_64 | 1,242,032 |
| `redlines`, universal, signed, in the app | **2,510,624** |
| `redlines-desktop`, universal | 39,388,672 |
| The whole app, on disk | 41 MB (17.9 MB zipped) |

So it adds 2.5 MB, or 6%. The spec's estimate was 2.3 MB.

**What this means for everyone's builds:**

- **`cargo` in `src-tauri` now fails without the file:** ``resource path `binaries/redlines-aarch64-apple-darwin` doesn't exist``. That hits `cargo clippy`, `cargo test` and CI's Linux `desktop` job, and every worktree. An empty file is enough for tauri-build, so CI can `touch` it, or better, build it.
- **tauri-build also copies the file to `target/<profile>/redlines`, and it can go stale.** It reruns on a newer modification time, so copy without preserving it: `shutil.copy`, not `copy2`. That's how the 0-byte program above got into a dev run.
- **So a dev build needs no special path.** `current_exe().parent()/redlines` is right in `tauri dev` and in the app alike.
- `release.yml` compiles with `tauri build --no-bundle` and then bundles with `tauri bundle`. The spike ran it as one step. `beforeBuildCommand` belongs to the first, and the files stay there for the second.
- Port 1420 is taken when another worktree is running `tauri dev`. `tauri dev --config '{"build":{"devUrl":"http://localhost:1431","beforeDevCommand":"… pnpm dev --port 1431 --strictPort"}}'` gets around that.
